Rules that hold through every phase
flutter analyze lib
Must stay at 0 errors after every phase. Never commit a phase with analyze errors.
flutter test
18/18 must pass. The 17 SMS parser parity tests + 1 pipeline stress test must never regress — none of those tests touch UI code.
bottomSafeWithFloatingNav
220dp bottom padding on every screen. If any screen's content hides under the pill nav on device, it must be fixed before that phase is closed.
AlertDialog parity
Dialogs that are AlertDialog in the Kotlin reference stay AlertDialog. CalendarAdd is the only full-screen push exception per PARITY_AUDIT.md.
KSh truncation
formatCurrency() output is always truncated to integer, never rounded. JetBrains Mono with tabular-nums everywhere amounts appear.
database.g.dart
Never edited manually. If any schema hint is needed, run dart run build_runner build --delete-conflicting-outputs.
Stubs stay stubs
ReviewQueue, Quarantine, PaybillRegistry, Categorize, FeeAnalytics, Learning, Export file-write, ScreenLockSettings, NotificationSettings, SmsImportHealth — no logic is added to these during the revamp. Visual treatment only.
One phase at a time
Each phase is approved (analyzed, tested, device-verified) before the next starts. No parallel edits across phases.
